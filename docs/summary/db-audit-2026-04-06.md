# Database Audit Summary — April 6, 2026

## What was audited

- Supabase database permissions and RLS policies
- pgvector schema placement and embedding search support
- Cache-table access patterns and pruning strategy
- `src/lib/enrich.ts` film-mapping lookup performance

## What was found

1. `vector` extension was installed in `public` instead of `extensions`.
2. Several cache tables still allowed anonymous SELECT reads.
3. `getFilmMappings()` fetched too much data and filtered in memory, creating an IO hotspot.
4. `pg_cron` was not enabled for automated cache pruning.
5. Index bloat was clarified as a maintenance concern, not a functional outage.

## What was fixed

- Moved `vector` to the `extensions` schema and rebuilt the embeddings table, index, and function to use `extensions.vector`.
- Tightened cache and movie lookup RLS policies to authenticated-only reads.
- Rewrote `getFilmMappings()` to fetch only requested URIs server-side using chunked parallel queries.
- Fixed `withTimeout()` timer cleanup and removed the unsafe type cast in the mappings path.
- Enabled `pg_cron` and scheduled daily 30-day pruning for cache tables at 03:20 UTC.

## Remaining manual action

- Supabase Dashboard → Authentication → Settings → Password Security → enable **Leaked Password Protection (HIBP)**.

## Notes

- The database work was applied directly through Supabase migrations and remote schema changes.
